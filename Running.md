# Running MiqorAI

## Local development (npm only - no Docker required)

Requirements: Node 22 (`.nvmrc`; run `nvm use`), npm, a PostgreSQL database
(local install or a Supabase dev project). Redis is optional locally: the dev
scripts start an embedded Redis (`redis-memory-server`) when nothing listens on
127.0.0.1:6379.

```bash
npm install                    # root workspace: packages/* + the five portals (one lockfile)
npm install --prefix server    # API (own lockfile)
cp server/.env.example server/.env   # then set DATABASE_URL, NODE_ENV=development, secrets
npm run db:migrate --prefix server
npm run db:seed --prefix server      # demo data - WIPES the database DATABASE_URL points at
```

Start everything (API + all portals):

```bash
npm run dev:full
```

| App | URL |
|-----|-----|
| API | http://localhost:3000 (health: `/health`) |
| Patient portal | http://localhost:5173 |
| Hospital portal | http://localhost:8080 |
| Insurance portal | http://localhost:8081 |
| Pharmacy portal | http://localhost:8082 |
| Admin portal | http://localhost:8083 |

Other entry points: `npm run dev:core` (API + patient + hospital), `npm run dev:api`
(API only), `npm run dev:worker --prefix server` (standalone worker; the API runs the
worker loops inline unless `WORKER_INLINE=false`). The portals proxy `/api` to
`http://localhost:3000` in dev, so `VITE_API_URL` can stay unset locally.

AI service (optional): see `miqorai-ai-service/README.md`; settings in
`miqorai-ai-service/.env.example`. Without it, set `MIQORAI_AI_MOCK=true` on the API.

Mobile: `cd mobile_patient && npm start`; point `EXPO_PUBLIC_API_URL` at your
machine's LAN IP (`mobile_patient/.env.local.example`).

## Production topology

- API + background worker: Render (`render.yaml`), `WORKER_INLINE=false` on the API
- Database / storage: Supabase Postgres + Storage; Redis: managed (Upstash or similar)
- Portals: Vercel projects (`<portal>/vercel.json`); patient portal also on GitHub Pages
- AI service: Hugging Face Space (`hf-space-publish/`, generated by `scripts/sync-hf-space.ps1`)
- Mobile: Expo EAS

Details, Vercel project settings and env templates: [DEPLOYMENT_MAP.md](./DEPLOYMENT_MAP.md).

## Portable alternative: Docker + Kubernetes

Docker only builds images (`deploy/docker/`, always from the repo root);
Kubernetes (`deploy/k8s/`, Kustomize) describes how they run. See
[deploy/k8s/README.md](./deploy/k8s/README.md). Neither is needed for local development.

## Checks

```bash
npm run test:production:wiring   # static deploy/env wiring checks

```
